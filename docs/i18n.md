## 1. Overview

The project uses a **two-layer internationalization** design:

| Layer | Engine | Scope | Root namespace |
| --- | --- | --- | --- |
| UI layer | `vue-i18n` | Vue component templates / Composition API (header, panel, footer, etc.) | `leaferEditorLayouts` |
| Kernel layer | `i18next` | Vue-agnostic kernel logic (context menu, floating toolbar, etc.) | `leaferEditorPlugins` |

Why this split: the kernel `LeaferEditor` is a **standalone, reusable library** and should not hard-depend on Vue or its i18n solution. The kernel therefore uses the framework-agnostic `i18next`. The layout UI, on the other hand, is entirely made of Vue components and uses the more mature `vue-i18n`. The two layers stay in sync at runtime through the current-locale variable `localeType`.

In addition, the UI component library **Arco Design Vue** has its own locale packs, synchronized separately through `a-config-provider`.

## 2. Two-Layer i18n Architecture

```
                        ┌─────────────────────────────┐
                        │  src/i18n/consts.ts          │
                        │  localeType (ref, single src)│
                        └──────────────┬──────────────┘
                                       │ watch
                        ┌──────────────▼──────────────┐
                        │  src/App.vue                 │
                        │  watch(localeType) syncs all │
                        └───┬───────────┬───────────┬─┘
                            │           │           │
             i18n.locale ───┘           │           └─── setLocale()
             (vue-i18n)                  │                (i18next)
                                         │
                              arcolocale (computed)
                              a-config-provider
                              (Arco Design locale)
```

- `localeType` is the single source of truth (a `ref` in `src/i18n/consts.ts`).
- Changing `localeType.value` anywhere triggers the `watch` in `App.vue`, which synchronizes vue-i18n, i18next, and Arco.
- Arco's locale follows automatically via the `arcolocale` computed property — no manual call needed.

## 4. UI Layer: vue-i18n

### 4.1 Locale Constants and Current Locale

`src/i18n/consts.ts` defines the code constants and display names for all supported languages, plus the global current locale `localeType`:

```ts
import { ref } from "vue";

export const zh_CN = "zh-CN";
export const en_US = "en-US";
export const ja_JP = "ja-JP";
// ... other locale code constants

const languageLabels: Record<string, string> = {
    [zh_CN]: "中文",
    [en_US]: "English",
    [ja_JP]: "日本語",
    // ...
};
export const getLanguageLabel = (language: string) => languageLabels[language] || language;

export const localeType = ref(zh_CN);   // Single source of truth: current locale
```

> Note: `consts.ts` lists 13 locale codes, but **only some languages have registered messages** (see below). The rest are placeholders reserved for future extension.

### 4.2 The vue-i18n Instance

`src/i18n/i18n.ts` creates the `vue-i18n` instance (Composition API mode) and registers the app-level message packs:

```ts
import { createI18n } from "vue-i18n";
import { computed } from "vue";
import { arcolocaleOptions } from "./arcoI18n";
import { zh_CN, en_US } from "./consts";
import zh from "../locales/zh-CN.json";
import en from "../locales/en-US.json";

const messages = {
    [en_US]: en,
    [zh_CN]: zh,
};

// langOptions: intersection of app message locales and Arco locales
export const langOptions = computed(() => {
    const msgKeys = Object.keys(messages);
    return arcolocaleOptions.value.filter(item => msgKeys.includes(item));
});

const i18n = createI18n({
    legacy: false,            // Composition API mode
    locale: zh_CN,            // Default locale
    fallbackLocale: zh_CN,    // Fallback locale
    globalInjection: true,    // Globally inject $t
    messages,
});

export default i18n;
```

Key points:

- `legacy: false`: Composition API mode; components get `t` via `useI18n()`.
- `globalInjection: true`: `$t('...')` can be used directly in templates.
- Both the default and fallback locales are `zh-CN`.
- `langOptions` filters for languages that have **both** app messages and an Arco locale pack — useful as a data source for a language selector.

### 4.3 Arco Design Locale

`src/i18n/arcoI18n.ts` maps project locale codes to Arco Design locale objects:

```ts
import { computed } from "vue";
import zhCN from "@arco-design/web-vue/es/locale/lang/zh-cn";
import enUS from "@arco-design/web-vue/es/locale/lang/en-us";
import { zh_CN, en_US, localeType } from "./consts";

const locales: Record<string, any> = {};
locales[zh_CN] = zhCN;
locales[en_US] = enUS;

export const arcolocale = computed(() => locales[localeType.value] || zhCN);
export const arcolocaleOptions = computed(() => Object.keys(locales));
```

It is applied in `App.vue` via `a-config-provider`:

```vue
<a-config-provider :locale="arcolocale">
    <RouterView />
</a-config-provider>
```

This way, Arco components' built-in text (e.g. pagination, date pickers) switches automatically with `localeType`.

### 4.4 Merging Layout Messages

The bulk of the layout UI messages live in `src/LeaferEditor/layouts/locales/` under the root key `leaferEditorLayouts`, and are merged into vue-i18n when `layout.vue` mounts:

```ts
// src/LeaferEditor/layouts/layout.vue
import { useI18n } from "vue-i18n";
import { locales } from "./locales";

const i18n = useI18n();
for (const key in locales) {
    i18n.mergeLocaleMessage(key, locales[key]);
}
```

`locales/index.ts` currently registers `zh-CN` and `en-US`:

```ts
import zh from "./zh-CN.json";
import en from "./en-US.json";

export const locales: Record<string, typeof zh> = {
    "zh-CN": zh,
    "en-US": en,
};
```

Components reference messages by namespace, for example:

```vue
<span>{{ $t('leaferEditorLayouts.footer.copyright') }}</span>
```

```ts
import { useI18n } from "vue-i18n";
const { t } = useI18n();
const label = t('leaferEditorLayouts.panelRight.attribute.arrow.title');
```

## 5. Kernel Layer: i18next

The kernel uses the framework-agnostic `i18next`, with its entry point at `src/LeaferEditor/i18n/index.ts`:

```ts
import i18next from 'i18next'
import zh from './locales/zh-CN.json'
import en from './locales/en-US.json'

const instance = i18next.createInstance()

instance.init({
    lng: 'zh-CN',
    fallbackLng: 'zh-CN',
    resources: {
        'zh-CN': { translation: zh },
        'en-US': { translation: en },
    },
})

export const t = (key: string, options?: Record<string, any>): string =>
    instance.t(key, options)

export const setLocale = (locale: string) => instance.changeLanguage(locale)
export const getLocale = (): string => instance.language
export const addResources = (locale: string, resources: LocaleJSON) =>
    instance.addResourceBundle(locale, 'translation', resources, true, true)
```

These APIs are re-exported from the kernel entry (`src/LeaferEditor/index.ts`):

```ts
export { setLocale, getLocale, addResources, t } from './i18n';
```

Kernel plugins call `t` directly when they need text, e.g. the context menu and floating toolbar:

```ts
// src/LeaferEditor/plugins/contextMenu.ts
import { t } from "../i18n"
// ...
{ title: t("leaferEditorPlugins.add.rect.title"), ... }

// src/LeaferEditor/plugins/toolBar.ts
import { t } from "../i18n"
{ id: "copy", help: () => t("leaferEditorPlugins.copy"), ... }
```

The kernel root namespace is `leaferEditorPlugins`, currently containing groups such as `copy / cut / paste / zoom / grid / zIndex / add / operate`.

> Unlike the UI layer, the kernel `t` returns a **plain string, not a reactive value**. The context menu and toolbar read their text at creation time, so after switching language at runtime, an already-built menu must be rebuilt (reload the DOM) to reflect the new language.

## 6. Runtime Language-Switching Mechanism

`App.vue` is the hub that synchronizes all three locales:

```ts
import { useI18n } from 'vue-i18n';
import { watch } from 'vue';
import { arcolocale, localeType } from './i18n';
import { setLocale, addResources } from './LeaferEditor';

const i18n = useI18n();

// Dynamically register Japanese messages (app layer + kernel layer)
i18n.mergeLocaleMessage(ja_JP, ja)
addResources("ja-JP", { leaferEditorPlugins: { /* ... */ } })

watch(localeType, (newVal) => {
    i18n.locale.value = newVal;   // 1. vue-i18n
    setLocale(newVal);            // 2. i18next
});
```

Combined with `<a-config-provider :locale="arcolocale">` in the template, the complete switching chain is:

1. Change `localeType.value`;
2. `watch` fires → `i18n.locale.value = newVal` (Vue component text updates);
3. `watch` fires → `setLocale(newVal)` (kernel plugin text updates);
4. The `arcolocale` computed changes → `a-config-provider` updates (Arco component text updates).

A minimal switching example is in `src/views/actions/githubBtn.vue`:

```ts
import { localeType } from '../../i18n';
import { zh_CN, en_US, ja_JP } from '../../i18n/consts';

const locales = [zh_CN, en_US, ja_JP];
const onClick = () => {
    n = (n + 1) % locales.length;
    localeType.value = locales[n] || zh_CN;
};
```

> The project currently has **no** locale persistence (localStorage) and **no** browser-language auto-detection; it always defaults to `zh-CN`. To persist, read `localStorage` when initializing in `consts.ts` and write back in the `watch`.

## 7. Using Translations in Code

### 7.1 Vue Components (UI layer)

```vue
<template>
    <!-- Use directly in templates -->
    <span>{{ $t('leaferEditorLayouts.footer.addPage') }}</span>
</template>

<script setup lang="ts">
import { useI18n } from 'vue-i18n';
const { t } = useI18n();
const title = t('leaferEditorLayouts.panelRight.index.attribute');
</script>
```

### 7.2 Parameters and Interpolation

Message JSON can use `{name}` placeholders:

```json
{ "errorImageSize": "Image size cannot exceed {size}MB" }
```

```ts
t('leaferEditorLayouts.panelRight.attribute.image.errorImageSize', { size: 10 })
```

### 7.3 Kernel Logic / Plugins (Kernel layer)

```ts
import { t } from "../i18n";
const text = t("leaferEditorPlugins.add.title");
```

## 8. Adding a New Language

Taking `fr-FR` as an example, the complete steps are as follows.

### Step 1: Add the locale code and display name

In `src/i18n/consts.ts` (the constant `fr_FR` already exists; add it if not, and add the display name to `languageLabels`).

### Step 2: Register the Arco locale

In `src/i18n/arcoI18n.ts`:

```ts
import frFR from "@arco-design/web-vue/es/locale/lang/fr-fr";
import { fr_FR } from "./consts";

locales[fr_FR] = frFR;
```

> If Arco has no matching locale pack, `arcolocale` falls back to `zh-CN` automatically without affecting operation.

### Step 3: Add app-level messages and register them

1. Create `src/locales/fr-FR.json`;
2. Register it in the `messages` object in `src/i18n/i18n.ts`:

```ts
import fr from "../locales/fr-FR.json";
const messages = {
    [en_US]: en,
    [zh_CN]: zh,
    [fr_FR]: fr,
};
```

### Step 4: Add layout UI messages and register them

1. Create `src/LeaferEditor/layouts/locales/fr-FR.json` (copy `zh-CN.json`, translate it, and keep the `leaferEditorLayouts` root key and all key paths);
2. Register it in `src/LeaferEditor/layouts/locales/index.ts`:

```ts
import fr from "./fr-FR.json";
export const locales: Record<string, typeof zh> = {
    "zh-CN": zh,
    "en-US": en,
    "fr-FR": fr,
};
```

### Step 5: Add kernel messages and register them

1. Create `src/LeaferEditor/i18n/locales/fr-FR.json` (keep the `leaferEditorPlugins` root key);
2. Register it in the `resources` object in `src/LeaferEditor/i18n/index.ts`:

```ts
import fr from './locales/fr-FR.json'
resources: {
    'zh-CN': { translation: zh },
    'en-US': { translation: en },
    'fr-FR': { translation: fr },
},
```

### Step 6: Wire up the language selector

Add `fr_FR` to the language selector list (see `githubBtn.vue`). On switching, the `watch` in `App.vue` synchronizes all three automatically.

> Alternatively, you can use **runtime dynamic registration** (as `App.vue` does for Japanese) via `i18n.mergeLocaleMessage` + `addResources`, avoiding changes to the static `messages` / `resources` registration. Either approach works.

## 9. Extending Translations at Runtime

For messages supplied dynamically by third parties or business logic, you can inject into each layer at runtime.

**UI layer (vue-i18n)**:

```ts
import { useI18n } from "vue-i18n";
const i18n = useI18n();
i18n.mergeLocaleMessage("fr-FR", {
    myModule: { hello: "Bonjour" },
});
```

**Kernel layer (i18next)**:

```ts
import { addResources } from "./LeaferEditor";

addResources("fr-FR", {
    leaferEditorPlugins: {
        copy: "Copier",
        // ... remaining keys
    },
});
```

> The `resources` type of `addResources` is the structure of the kernel `zh-CN.json` (`LocaleJSON`). The fourth parameter `deep=true, overwrite=true` means deep-merge and overwrite keys with the same name.

## 10. Notes and Best Practices

1. **Keep both layers in sync**: when adding a language, handle both the UI layer (`layouts/locales` + `locales`) and the kernel layer (`LeaferEditor/i18n/locales`), otherwise you get a mix of "panels translated, context menu still in Chinese".
2. **Do not rename namespaces**: the UI layer uses `leaferEditorLayouts` and the kernel layer uses `leaferEditorPlugins`, which makes them easy to distinguish and merge.
3. **Keep key paths complete**: translation JSON should mirror the source language's key structure exactly; missing keys fall back to `fallbackLocale` (`zh-CN`).
4. **Kernel text is not reactive**: the kernel `t` is evaluated only when called; after a runtime language switch, the context menu / toolbar text requires a rebuild to refresh.
5. **Arco fallback**: languages not registered in `arcoI18n.ts` make Arco components fall back to Chinese, without affecting custom app messages.
6. **Default and fallback locale**: both are `zh-CN`; after adding a language, consider explicitly setting a `fallbackLocale` strategy.
7. **Persistence / auto-detection (optional)**: not implemented currently. To add it, initialize `localeType` in `consts.ts` and write back to storage in the `watch` in `App.vue`.
8. **`langOptions`**: it is the intersection of "app message locales" and "Arco locales", suitable as a language-selector data source, avoiding options that have only Arco support (or vice versa).
